01 / Read first

What this application is

A native C++17 / Dear ImGui RF monitoring application for USRP B210 and X310 receivers. It turns finite IQ captures into spectrum observations, supported Wi-Fi and LoRa packets, persistent inventory, passive security evidence, optional drone broadcasts, experimental waveform measurements and aircraft-model candidates.

One receiver, one selected band

The scanner owns the radio. Browsing a workspace does not select its band. Explicit monitoring controls change acquisition.

Different evidence, different meaning

An energy cluster, decoded MAC address, reported DroneID and ML score are separate observations. None automatically verifies a physical device.

Optional consumers

Cyclostationary, DJI, Remote ID and model workers consume existing observations. They do not own a second receiver.

The GUI retains 200 rows. Standard search caps at 32 packets per SF/BW/polarity hypothesis and 1, 100 data symbols per extraction. Grouping caps comparison probes at 1, 048, 576; remaining rows stay separate. Boxcar decimation is not an interference-rejecting channelizer. A LoRa capture directory has manifest.json and iq.cf32_le: interleaved float 32 I/Q, little-endian, eight bytes per complex sample. The loader bounds metadata to 64 KiB and IQ to 32 million samples (256 MB), and checks exact file size, finite values and a 64-bit FNV-1a checksum. Settings and receiver configuration

Monitoring setup exposes device selection, connect/disconnect, band, channel/lock, gain/AGC, detection threshold, capture duration and laboratory mode. Scale, compact layout and legacy presentation affect only the UI.

Sample-rate control added 22 October: Settings → Monitoring setup now has Custom Wi-Fi sample rate and an MSps input (1–200). It applies to both Wi-Fi bands on Connect/Reconnect. Turning the checkbox off restores the existing device default. The latest requested and actual UHD rates are shown separately; a failed capture shows actual rate unavailable. Custom requests bypass the historical X310 20 MSps default. LoRa scan/listen rates remain independent. AGC and manual gain now occupy the row below Threshold.

Rate support depends on the receiver and decoder: legacy Wi-Fi OFDM currently accepts actual input rates of 20–64 MSps. Processing overlap is admitted using the requested rate and rechecked against the returned actual rate; a rate exceeding the overlap memory budget uses inline processing. A coerced UHD rate is reused for the same request rather than rebuilding the stream every capture. The control sets output IQ rate, not an independent ADC clock.

13 / Backend deep dive

Acquisition, clocks and spectrum

  • CaptureTiming records device sample-zero time, host before/after uncertainty, overflow indices and optional resume time, requested sample count, timeout/exception, RF LO/DSP tune results and gain read-back where available.
  • Frame time derives from sample coordinates in a valid device-clock region. Host timestamps are not sample-exact. A new receiver session or context breaks comparisons that require continuity.
  • Spectrum estimates a percentile noise floor, seeds/grows segments with hysteresis, merges small gaps and guards DC/LO and filter-edge artifacts. Max-hold across short captures helps retain intermittent energy.
  • Bandwidth classification remains heuristic. DeviceRegistry merges compatible sightings, smooths power and expires per-band observations. Cadence estimates are lower bounds, not a physical-radio census.
  • Error paths report transport failure and scanner health. A status file, retained row or low packet count alone does not prove a live healthy stream.

14 / Backend deep dive

Wi-Fi decoding and persistent enrolment

DSSS performs chip-grid resampling, Barker despreading/timing search, differential DBPSK, descrambling, sync/SFD, PLCP CRC and full MPDU FCS. OFDM downmixes/resamples to 20 MSps, detects training, estimates frequency/timing/channel, decodes SIGNAL and coded payload, then checks FCS. Its current entry point accepts 20–64 MSps and burst spans≤ 6 ms; these bounds do not add modern Wi-Fi PHYs.

MAC parsing extracts supported addresses, frame types, sequence/retry and readable management/security fields. Vendor/OUI and WPS retain provenance. Missing/incomplete IEs cannot fabricate a downgrade. Transmitting valid unicast interfaces can create records; receiver-only or invalid/group transmitter addresses cannot.

At most 512 existing burst descriptors guide up to 4 windows of≤ 65, 536 samples, with 262, 144 complex samples total (2 MiB). First/last context and up to 2 guided interior windows retain exact source coordinates. At 20 MSps the maximum copied duration is 13.1 ms in potentially disjoint windows; higher rates shorten time support. Separate gaps or bursts are never concatenated.

The supervisor owns 8 preallocated 2 MiB slots. The child has 128 MiB address-space limit, 2 s request deadline and 64 KiB reply cap; it uses an inherited local socket, not a network service. Matched app/helper wire version 11 is required. Only the latest capture snapshot, with separate tile results, is retained internally.

Named-link release still needs independent family/mode truth, competing radios and unknown links, full-search false-match/miss evaluation, live candidate routing/recurrence, receiver passband and live load/endurance qualification. Lightbridge and other proprietary families have no validated distinguishing signature. Native prefix/span checks are implemented; offline recurrence does not establish recurrence in live separated tiles.
